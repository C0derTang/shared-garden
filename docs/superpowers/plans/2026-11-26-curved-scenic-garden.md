## Shared contracts and implementation

- `scenic-route.ts` owns `ScenicIsland`, `ScenicStop`, `ScenicEdge`, `ScenicRoute`, immutable `pocketCenter(type,section)`, and `ScenicNavigator.select/tick/update/interrupt/pose/selectedId`. Both camera and ribbon use the exact cubic `curvePoint` and shared bounded `edgeParameters`/analytic tangent. Path width is 1.44 m. Collectable route/edge WeakMap caches hold the flattened-segment BVH/tessellation; nearest distances must match brute force.
- Two primary ellipses have world centres `(18,60)` and `(18,102)`, radii 8 m in world x and 15 m in world z. Types 0–6 use the first; 7–12 the second. Inside types are 0,2,5,7,9,11; remaining types are outskirts. Organic pocket frames are deterministic. Tangent-matched cubic loop arcs, a curved bridge and a fitted woodland connection avoid original trunks/rocks. Additional used/next twelve-address sections occupy rounded loops centred `(18,160+(section−1)×60)` with world x/z radii 12/16; generate only used sections, never missing address gaps.
- Initial `overview:0`, then direct type stops, `overview:1`, remaining types, `house-rear` and `lake` form the main selectable itinerary. Transit nodes provide continuous woodland/shore/meadow travel without becoming extra UI stops. Overview eyes are terrain+8 m with 56° landscape/86° portrait lenses. Ordinary approaches use the existing aspect-aware garden lens. The rear eye is `houseToWorld([0,0,-HOUSE.depth−6])`, terrain+2.65 m, looking at the actual rear centre; lens 100° landscape/108° very wide/128° portrait. Lens and shortest-angle heading interpolate along the same graph; flower focus composes through `scenicPose` and restores the selected stop.
- `type-areas.ts` maps every actual/pending flower, care cue, seed, planting target, picking surface and accessible plot to the same stable frames. Route updates resolve a removed pending-only stop to a stable relevant type view, including mid-travel. Planting/lower holes do not move existing planted positions or rewrite state.
- `site-geography.ts` extracts original functions without changing values; `backyard-frame.ts` derives axes/rear origin from the original house frame. `site-surface.ts` samples the exact frozen Float32 landing ground facets. New planting roots are max(analytic terrain, original facet)+1 cm, path +2.5 cm. Original ground stays byte-identical. Additional ground tiles/corridors and exterior-only backdrops cover used sparse sections on both axes without overlapping the yard from above; triangle interiors must clear every ground layer.
- Actual landing uses the unchanged default `buildHouseMesh()`. `buildGardenHouseMesh()` augments that same world-frame model with a matching rear door/covered timber porch/rails/steps. Rear door material 10 stays static while the original front material 5 swings; shader scene/shadow/reflection functions share that guard. `garden-house-frame.ts` provides house-local caption occlusion, with no independent relocation/rotation.
- GardenV2 owns `selectedStop`; GardenWorld passes route/selection/blocking to the renderer. Persistent Back/native selector/Onward and projected existing-stop buttons use the same guarded selection. Fully clipped or UI-covered markers are hidden and remain keyboard reachable; actual nav and initial-hint bounds are reserved. Pointer capture preserves drag/cancel slop, including excursions outside a button. No WASD/pad/wheel/ground walking in scenic mode. Flower/UI priority, fields/overlays/scoped sheets, arrival, focus return, reduced motion, resize, blur/visibility and GPU recovery retain their existing contracts. Reconcile latest selection after focus reset to prevent a queued-frame return race.
- Preserve original caster/field RNG outputs. Garden-only low meadow filtering/cover uses the same painterly strokes and bounded used-island regions; no added activity plants or private data fetch in landing.
