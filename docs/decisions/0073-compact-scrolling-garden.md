## Compact composition and stable identity

One open C-shaped garden room occupies approximately worldx8..28,z49..79, with an actual curved walk, adjoining softly rectangular/scalloped soil terraces and original landscape views. The base tour order is Sunflower, Snapdragon, Rose, Hydrangea, Peony, Marigold, Tulip, Daisy, Cactus, Moonflower, Bluebell, Forget-me-not, Dandelion. Low/mid Marigold, Daisy and Bluebell beds fill the inside; the other ten frame the outside. Tall/warm framing flows into shorter/cool blooms. All13 types exist empty.

Six actual plants fit a terrace. Fixed species-specific mature envelopes include air/sway margins above canonical measured seeds1–300: radii0.14–0.40m and heights0.43–1.42m. Current growth never changes addresses. Same-type plants sort by immutable `planted_at`, then persisted spot, then ID; presentation rank supplies local slots. Persisted IDs/spots/seeds/growth/history/content are never rewritten. Ordinary later-created planting appends even when it fills a lower numbered hole. Equal-time historical records have deterministic spot/ID ties independent of input order/refresh; artificially inserting an older/equal creation timestamp can change ranks. This is not a claim that arbitrary historical insertion is append-only.

Next seed targets sit on the walk-facing rim of the last occupied terrace. No target-only overflow terrace is generated. Only actual occupied overflow modules extend the presentation; a sparse global spot12001 has no empty physical mileage. Geometry is generated only for actual occupied modules and13 targets, never for global address holes.

Actual overflow takes a short inland spur through the upper C-room gap after Daisy: first walk point(22,81), thenz81+4.1×ordinal, beds to its west, a rounded far-end turn and parallel return atx24 to the next base bed. The first actual connection measures7.431125m after the R1 stable-control correction. There is no duplicated empty13-type expansion loop. Base beds remain fixed; strict tests include the whole path width/camera margin, all bed rims and retained original solid capsules, including multiple occupied modules. Expansion retains unchanged edge identity/fraction and exact pose; a removed leg falls back to its relevant stable terrace anchor rather than an old global percentage/distance.

## One scroll authority and two navigation methods

A native vertical scrollport pins the world. Wheel/trackpad/touch inertia and page/navigation keys remain browser-owned. Monotonic per-leg mapping converts native scroll pixels into cumulative actual cubic-path arc distance:12px/metre on the brief surveyed woodland approach,80px/metre among flowers, with minimum80/300px per radian respectively for deliberate turns. The renderer, picking/care/seed anchors and aspect-aware lens sample that same distance and pose; no separate selected-stop reconciler or camera tween competes with it.

The directed tour includes the actual rear-house/porch/steps view and original surveyed woodland access before the garden room. Initial native position is the garden overlook; backward scrolling/Home reveals the rear porch. The tour does not wrap or teleport. GardenV2 removes Back/current/Onward, fixed-stop selectors/route markers and free walking. Existing legacy interactions stay intact.

Picker selection animates **native scrollTop only**, using one cancellable rAF writer (smoothstep,500–1600ms). Actual Chromium verification showed native smooth scrollTo could ignore reverse input, and cancel-to-current could consume its first delta. Canceling the rAF writer on wheel/pointer/navigation-key capture leaves that same native input and its inertia intact. An epoch rejects stale queued callbacks. Picker reopening, blur/hidden, activity/overlay, actual layout change, recovery and unmount also cancel it. Geometrically identical state refreshes do not reset travel. Reduced motion positions immediately and supports a newly accepted distance before the next GPU frame.

Normal activity/seed-hold close explicitly waits for the actual renderer's settled return, because paused frames can skip a readiness callback. Activity return preserves exact progress/heading/lens and focus; blocked input is discarded. A late close-focus callback preserves a newer intentional control/plot focus rather than reopening the previous species. These are lifecycle corrections, with no activity-rule change.

## Flower drawer

A right-edge44px-or-larger tab opens a panel below global chrome and inside safe-area bounds. All13 options contain only a canonical mature flower portrait and name: no emoji, counts, stages, descriptions or badges. Static lightweight WebP portraits come from the existing FlowerHero models, seed1, day lighting, with bloom framing; Dandelion uses its canonical mature puff. No extra live picker GPU contexts are created.

Selection navigates on the same tour, closes the panel and restores trigger focus; it does not plant or submit care. Escape/outside dismissal, a focus trap, pointer-captured drag/cancel rejection and independent panel scrolling are supported. Real flowers/seed marks and the hidden accessible plot list retain their separate activity priority.

## Independent review correction — surviving curves and image readiness

Review R1 found that recomputing cubic handles from current itinerary neighbors bent surviving edges on occupied expansion. Tangents now belong to immutable spatial slots: canonical base-room/access neighbors retain original controls, while outbound/return module tangents use virtual fixed neighbors independent of current occupied extent. Every surviving edge retains its control points and interior rendered eye/orientation/lens across first and subsequent ordinary occupied appends. Only the genuinely replaced shortcut/turn legs may fall back to their stable adjacent terrace. Far-turn IDs include their last occupied slot, so moving the turn cannot masquerade as unchanged geometry. The no-overflow tour/scene remains byte-identical to the reviewed candidate.

The browser matrix now waits with a bounded observable predicate for all13 exact expected portrait URLs to load with positive natural dimensions and decode. A fresh drawer mount is not image readiness; delayed images must wait and a genuinely missing image must still fail. No fixed sleep or waived asset assertion substitutes for this check.

Publish route remapping in the layout effect before paint so no submitted frame can combine a new itinerary with the old cumulative distance. At actual layout remap, preserve the conversion phase between the accepted fractional tour pixel and the browser's representable native CSS pixel. Apply that phase consistently in native→tour sampling and tour→native freeze/picker destinations; Home/End use actual DOM bounds. Subsequent native deltas retain their original size. Initial/no-overflow travel keeps zero phase and the original mapping. This is a DOM coordinate conversion, not a second camera position or an off-path override. Real browser regression compares submitted Float32 eye and full view/projection matrices exactly before/after refresh, then verifies the next trusted wheel renders on the shared path.

First overflow replaces only `terrace:4`→`terrace:1` (Daisy→Cactus). Later overflow replaces the old last-outbound→extent-specific-turn and that turn→old first-return legs. Exact surviving stop boundaries retain their exact stop ID before incoming-edge classification; a genuinely removed interior falls back to the nearest surviving boundary by old-route arc distance, with an earlier-boundary tie. This keeps a view beside Cactus at Cactus instead of sending it back to Daisy, and handles removed turns/other species without a type alias. Their removed edge IDs never survive. All other edges keep identical controls and interior eye/orientation/lens. Tests cover first, second and third occupied appends, every surviving edge at10/25/50/75/90%, and all four view aspects.

Both neighboring sides and native pixel quantization are tested for every surviving stop through first/later occupied remaps.
