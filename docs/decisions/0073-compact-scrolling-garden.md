# 0073 — Compact garden, continuous scrolling and flower picker

Approved user direction2026-11-26; implements [issue226](https://github.com/C0derTang/shared-garden/issues/226). Both native smooth scrolling and a right-side picture/name picker navigate one continuous tour. Beds may be adjacent and non-round; mature-bloom beauty and ease supersede0072's mandatory round islands/fixed stops. Selective static near-forest thinning is permitted while preserving the original front look. The original house frame, rear porch/steps, lake/shore, terrain, sun, far woodland, entry and private data/activity rules remain authoritative. [0004](0004-finalized-launch-rules.md), [0067](0067-garden-overhaul.md) and [0069](0069-measured-kuwahara-optimization.md) apply. No uncovered design choice is pending.

Conservative implementation choices under that discretion:

- One compact planted room follows a gently bending inland walk, world x near18, terrace centres near22 and z38 onward, approximately3.2m per species. Adjacent softly rectangular scalloped terraces replace separated soil discs. Canonical mature model envelopes inform fixed spacing, with separate type groupings, consistent oblique camera headings and tall blooms set deeper from the walk. All13types exist empty; multiple/full blooms inform composition.
- Sort each type by immutable `planted_at`, then persisted `spot`, then ID. Presentation rank supplies a compact address; global spot remains only the persisted action identity. Ordinary later planting appends even when filling a low hole; growth cannot reorder. Equal-time historical records use the documented spot/ID tie-break, invariant to input order/refresh. Inserting an artificially earlier/equal timestamp can change ranks; ordinary server creation timestamps append. No persisted field changes.
- Six-plant terrace modules use fixed approximately0.95m spacing. Base13terraces always exist; additional occupied and next-target modules alone append inland in first-plant timestamp/spot/ID order. Unoccupied global address gaps create no geometry, camera mileage or loops. A newly occupied overflow module joins the occupied chronology; target-only overflow terraces follow occupied ones. Existing occupied positions stay stable under ordinary appends. Work is proportional to plants plus13targets.
- A directed, nonwrapping tour follows actual shared cubic path geometry. Cumulative sampled arc distance provides one authority for native scroll position, picker anchors, rendered camera and picking lens. Smooth shortest-angle heading interpolation uses the same path samples. Retain edge identity and local fraction across layout expansion; activity return holds exact tour distance/heading. No competing selected-stop state or old Back/current/Onward/route-marker chrome ships in GardenV2; no arbitrary walking.
- A native vertical scrollport pins the world and supplies ordinary wheel/trackpad/touch inertia and keyboard page/home/end navigation. Picker selection uses native smooth scrolling to the corresponding type anchor, immediate under reduced motion. User input interrupts a glide. Arrival, overlays/fields, flower close-up/return, blur/hidden/recovery discard stale navigation and retain position; drawer scrolling is isolated.
- The right-edge tab opens an accessible dismissible panel with13options containing only canonical mature flower portraits and names. Static lightweight images are captured from existing canonical models; no emoji, counts or13runtimeGPUcontexts. Selection closes the panel and restores focus; Escape/outside dismissal and44px targets respect all four viewport/safe-area bounds.
- Save matching original front references BEFORE thinning at1280×800,390×844,844×390,800×600 for day/dusk/night and entry. Preserve frozen original factories and packedGPUdigests as provenance. Apply a small explicitly tested static near-forest subset consistently in both scenes; retain dominant front trunks/crowns/silhouette, terrain, house, farforest and rocks. Compare actual new render color/shadows/silhouette honestly; intentional allowed thinning is not unchanged caster output. Escalate a material front-look conflict.

No service/dependency upgrade, backend/schema, capacity/unlock, content/history, private state in public landing, cost/auth, or legacy change. Synthetic loopback browser evidence only; production fixture404 remains required. Dedicated isolated builder, full checks, exact-head independent review, requiredCI, merge and cleanup gates remain mandatory.
